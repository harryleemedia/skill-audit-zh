# 評估選定的技能

改編自 Anthropic skill-creator；見 ../ATTRIBUTION.md。只在被要求做行為評估時使用本文件，而不是每次掃描技能庫都用。

## 準備一次公平的比較

1. 選定一個具體的技能與 2–3 個具代表性的任務，使用使用者提供的或本地的非敏感測試夾具。在有必要時納入一個邊界案例。在檢視試驗輸出之前，先定義必要結果與主觀準則。任何測試都不應該只因為舊技能強制要求某個任意步驟就給予獎勵。
2. 在評估工作區中對原始技能及其相關資源做快照。準備一份簡化版副本，保留業務需求、資料、範例、安全邊界與運作不變量。記錄雜湊值與更動過的指令。絕不要為了設置試驗而編輯已安裝的原件。
3. 定義三個分支（arm）：`original`（原始）、`simplified`（簡化）、`baseline`（基準）。給每個分支相同的使用者請求、輸入事實、工具能力、資源與非程序性需求。基準組省略目標技能的程序性指令。如果資源無法公平地分離，就改為記錄一次「整包比較」，並且不要宣稱已隔離出指令品質。
4. 記錄確切的模型、推理強度、工具環境、輸入與資源雜湊值。使用使用者選定的模型（若明確要求則用 Astra）。絕不要悄悄替換成其他模型。執行條件必須一致；否則把比較標記為無效或探索性。
5. 把執行保持在隔離的輸出資料夾中。在仍能測試該能力的前提下，用測試夾具或草稿取代對外部的修改。不要只為了對技能做基準測試而執行正式環境的動作。如果測試本身需要新的權限或大量花費，先準備具體的測試計畫，並只針對缺少的授權提出請求。

## 在 Codex 中執行

當協作工具可用時，把彼此獨立的試驗委派給全新上下文的 Agent（若支援則使用 `fork_turns="none"`），並遵守可用的並行度。本技能授權在被要求的評估範圍內進行有限的並行試驗與審查工作。不要為內部試驗建立使用者擁有的任務。在 Agent 工作時，繼續準備測試夾具或撰寫報告。若支援，設定使用者明確要求的模型覆寫；絕不要捏造模型識別碼，也不要在沒有證據的情況下假設子 Agent 繼承了設定。

只給每個執行者任務本身、該分支專屬的指令、最少必要的輸入、共同需求，以及它的輸出目錄。不要給它疑似缺陷、預期的勝者、其他輸出或比較歷史。要求它儲存最終產出物，以及一份實際使用的工具／資源、完成狀態與不確定之處的記錄。若可取得，保留主機端的實際對話紀錄；執行者的自我回報本身是較弱的證據。

全新的對話上下文並不保證與已安裝的技能、繼承的指令或記憶隔離。檢查執行者可用的目錄與實際的技能讀取。如果基準組載入了目標技能或等效的輔助工具，就是受污染。如果無法用受支援的執行環境設定來防止這種情況，就回報**無法判定（inconclusive）**；單靠一句「不要使用這個技能」的提示不能證明隔離。不要為了強制隔離而更改使用者的全域設定。若已有獨立設定好的環境就使用它；否則停在計畫階段並揭露這項限制。

如果沒有獨立的 Agent 可用，改用受支援、具備等效控制的乾淨工作階段執行器。不要把同一個共享對話中的循序試驗當成獨立試驗來標記。這裡刻意不內附 `claude -p` 啟動器或未經驗證的 Codex CLI 包裝器。

先做一次初始試點（pilot）來抓出測試夾具與執行上的失敗。若要做出退役某個技能的決定，要測試多個具代表性的案例，並在結果接近或波動時重複執行。試點是初始訊號。在得到明確且有限的結果後，不要無止境地擴大；回報涵蓋範圍即可。

每次執行都依 [data-contracts.md](data-contracts.md) 中的格式記錄。缺少的遙測資料標記為 `null`；不要用字元數估算 token，也不要把缺少的指標當成零。把實際執行的牆鐘時間與評估者時間分開記錄。記錄被中斷、失敗、略過與受污染的試驗；絕不要悄悄丟棄它們。

## 判定結果

使用 [grader.md](grader.md) 從實際產出物評估客觀準則。在有用時使用確定性檢查，特別是檔案有效性、計算與資料對輸入的忠實度。在所有分支中保留準則與未知結果。

對於主觀準則，把輸出標記為 A/B（或 A/B/C），去除會洩漏分支的路徑名稱與中繼資料，然後使用 [comparator.md](comparator.md)。把私密的對應表放在評審的上下文之外。隨機化呈現順序。先凍結評分標準；評審不應該在看到哪個輸出最精緻之後才發明成功準則。對於個人品味，人類的偏好具有權威性。模型評審提供的是證據與暫定意見，而不是關於風格的客觀判決。

評分之後，使用 [analyzer.md](analyzer.md) 把觀察到的失敗與具體指令連結起來。區分相關性與已證實的因果。一個在所有分支都通過的斷言可能是有用的最低要求，但不能證明技能的價值。

## 報告

```text
python <skill-dir>/scripts/report.py benchmark <evaluation-dir>/results.json --out <evaluation-dir>/benchmark.html
```

這會產生 HTML 審閱報告，以及旁邊的一份 JSON 摘要。除了指標之外，也要檢視個別輸出。讓失敗的執行保持可見，只把明確無效／受污染的比較從有效執行的彙總中排除。說明排除項與缺少的遙測資料。彙總比較只使用模型、推理強度、環境與輸入都一致的匹配案例／重複配對。

建議保留、簡化、進一步調查，或考慮退役。每項建議都要以測試過的任務涵蓋範圍、產出物與有意義的差異來支持。單靠低使用率不足以支持退役。保留原件；只在被要求時才套用建議。
