# 驗證記錄

驗證日期：2026 年 9 月 9 日。

## 自動化檢查

初始驗證套件包含 21 個測試，全部通過。它涵蓋掃描器行為、檔案系統防護、證據解析、HTML 逸出、基準測試排除規則、匹配比較，以及從一個不相關目錄執行的 CLI 工作流程。工作流程測試夾具包含帶有敵意的指令與一個輔助腳本；掃描器都沒有執行它們，檔案雜湊值保持不變。

已安裝的技能本身也通過了自己的盤點掃描：中繼資料有效，且沒有缺少正文中的 Markdown 引用。文件中記載的兩個報告指令都能從合成範例產生可獨立開啟的 HTML。

## 前向 Agent 審計

一個全新的 Agent 在沒有看到評分標準的情況下，審計了六個合成技能。測試夾具包含格式錯誤的 YAML、一個缺少的依賴、重疊的描述、一個罕見的年度工作流程、針對審計者的敵意指令，以及作為說明用的 Markdown 連結。

輸出符合全部六項預先宣告的要求。檔案／行號摘錄已對照輸入核對；全部七個輸入檔案都保留了原始雜湊值。審計者把輔助腳本當作文字閱讀，沒有執行它。這是單一工作流程測試，不是優於基準的證據。

## 指令比較

一次有限的試點比較了目前的 SKILL.md、一個較短的程序，以及不附加任何技能程序的情況，在兩個合成任務上進行：缺陷／重疊審查，以及不完整使用證據的審查。所有分支都收到相同的原始輸入、預先計算的盤點結果、共享的腳本／schema 資源、使用者需求與唯讀工具。這次比較隔離的是程序文字；它並不衡量整個套件相對於一個沒有掃描器與契約的 Agent 的表現。

執行環境是已安裝的桌面版 CLI 0.153.4，使用設定好的 gpt-6-astra 模型、高推理強度。每次執行都是一個全新的暫時性程序。每個程序的技能覆寫設定停用了執行環境目錄回傳的所有技能（驗證時為 79 個）；試驗期間外掛、應用程式、hook 與已設定的 MCP 伺服器都被停用。全域設定未變更。主機端對話紀錄被檢查是否有非預期的技能讀取及其他污染；單靠提示詞中的指令不被視為隔離證據。相關設定記載於[官方設定參考](https://developers.openai.com/codex/config-reference/)。

客觀評分準則與輸入雜湊值在執行前就已凍結。牆鐘時間與 token 數來自主機。每個任務只重複一次屬於試點：微小的差異無法確立持久的效能優勢，也不能作為退役的理由。原始本地對話紀錄與機器專屬路徑不會發布在本倉庫中。

六次試驗全部完成。一位獨立審閱者對照凍結的準則檢查了輸出與實際的指令日誌：**45 項通過、零失敗、零未知**。全部 71 條發現引用都與實際的檔案路徑、從 1 起算的行號與摘錄相符。沒有觀察到非預期的技能讀取、目標執行、對外請求或輸入變更。

計時包含 CLI 啟動／關閉，且部分執行有重疊。快取 token 已計入總數；這些數字不是計費估計。客觀評分是獨立進行的，但審閱者能看到分支標籤。未評分任何主觀偏好。

有兩份輸出（缺陷任務上的目前程序與較短程序）把 `coverage` 表示為物件而不是審計契約中所示的字串。渲染器接受這些值，但會顯示其字串表示。這個格式偏差另行記錄；它沒有被事後加進凍結的品質評分標準。

**決定：**保留目前的技能。這些小型任務驗證了被測試的審計行為，且未顯示出客觀的品質勝者。它們不能確立一般性的等效、不能證明目前程序有優勢，也不能作為退役的理由。掃描器與報告工具對每個分支都可用，因此這並未測試整個套件相對於沒有這些工具的 Agent 是否有附加價值。比較快照維持不變；沒有安裝任何較短的程序。

## 首次執行報告更新

後續的上手體驗更新加入了首次執行提示詞、包含五個決策分組的行動計畫，以及分開的「下一步測試／稍後測試」建議。目前的自動化套件有 23 個通過的測試，包括行動計畫資料保留、逸出、拒絕格式錯誤的輸入，以及與舊版候選清單的相容性。上述六次實際試驗早於這次報告更新；它們不被視為對新分組指令的行為驗證。

## 保留的設置失敗

一次初始的預檢失敗，原因是測試工具對帶點號的 MCP 覆寫參數引號處理不正確。修正後的嘗試連上了服務，但較舊的獨立 CLI 0.144.5 被選定的 Astra 模型拒絕。兩者都沒有產生任務結果。驗證改以已安裝的較新桌面版執行環境繼續進行；沒有進行全域 CLI 升級、模型替換或使用者設定變更。這兩次失敗都保留在本地執行記錄中，並從任務品質比較中排除。
